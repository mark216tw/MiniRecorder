## 2. 整體架構

採用分層架構（UI → ViewModel → Repository → Data Source），並以 Hilt 進行依賴注入。

```
┌───────────────────────────────────────────────────────────────┐
│  UI Layer（Jetpack Compose）                                  │
│  MainActivity / AppNavHost / Screens / Components / Widget     │
└───────────────▲───────────────────────────────────────────────┘
                │ StateFlow / collectAsStateWithLifecycle
┌───────────────┴───────────────────────────────────────────────┐
│  Presentation Logic（ViewModel）                              │
│  RecordVM / ListVM / PlayerVM / SettingsVM / DisplayVM        │
└───────────────▲───────────────────────────────────────────────┘
                │ suspend / Flow
┌───────────────┴───────────────────────────────────────────────┐
│  Domain / Data Layer                                          │
│  RecordingRepository（檔案 + DB）                             │
│  SettingsRepository（DataStore）                              │
│  RecordingStateHolder / PlaybackController（單例狀態）        │
└───────────────▲───────────────────────────────────────────────┘
                │
┌───────────────┴───────────────────────────────────────────────┐
│  Platform / System Services                                   │
│  RecordingService（FGS 錄音） / PlaybackService（MediaSession）│
│  AudioRecorderEngine / SilenceDetector / Room / FileProvider   │
│  QuickRecordActivity / RecordingTileService / RecordWidget     │
└───────────────────────────────────────────────────────────────┘
```

### 分層職責

- **UI Layer**：Compose 畫面與元件，只負責呈現狀態與轉發事件。
- **ViewModel**：將 Repository / 單例狀態的 Flow 轉為畫面狀態（`StateFlow`），處理使用者操作。
- **Data Layer**：`RecordingRepository` 封裝 Room DAO 與檔案系統；`SettingsRepository` 封裝 DataStore。
- **單例狀態**：`RecordingStateHolder`（錄音 UI 狀態）與 `PlaybackController`（播放狀態）為跨畫面共享的
  `@Singleton`，讓 Service 與 UI 可透過 Flow 同步。
- **Platform Services**：前景服務、MediaSession、Tile、Widget 等系統整合。

## 4. 資料模型

Room 資料庫（`mini-recorder.db`，version 2）包含四個實體：

| 實體 | 資料表 | 說明 |
| --- | --- | --- |
| `Recording` | `recordings` | 錄音中繼資料（標題、檔案路徑、時間、長度、大小、聲道、取樣率、MIME） |
| `Tag` | `tags` | 標籤（名稱唯一、色相 0–359） |
| `RecordingTagCrossRef` | `recording_tags` | 錄音與標籤的多對多關聯（複合主鍵 + 外鍵 CASCADE） |
| `Marker` | `markers` | 錄音要點（時間戳、註記、建立時間，外鍵 CASCADE） |

- `RecordingWithTags` 為 `@Relation` + `Junction` 的關聯檢視物件。
- Schema 由 KSP 匯出至 `app/schemas/`。
- `RecordingDao.setTags` 使用 `@Transaction`：先清除關聯，再依名稱 upsert 標籤並建立關聯。

### 偏好設定（DataStore）

`AppSettings` 欄位與預設值：

| 欄位 | 預設 | 範圍 / 說明 |
| --- | --- | --- |
| `channelMode` | MONO | MONO / STEREO |
| `effectsEnabled` | true | 降噪 / 回音消除 / AGC |
| `silenceSkip` | false | 是否跳過靜音 |
| `silenceThresholdDb` | -40 | -60 ～ -10 |
| `silenceMinDurationMs` | 1200 | 300 ～ 5000（每 100 ms） |
| `maxDurationMin` | 60 | 30 ～ 180（每 30 分） |
| `warningsEnabled` | true | 時間提醒 |
| `themeMode` | SYSTEM | SYSTEM / LIGHT / DARK |
| `themeHue` | 226 | 0 ～ 359 |

`SettingsRepository` 以 `stateIn(..., SharingStarted.Eagerly, ...)` 提供 `settingsState`，
供 UI 與 Service 同步讀取。

## 5. 錄音管線（Audio Pipeline）

`AudioRecorderEngine` 是核心，運作於獨立執行緒（`THREAD_PRIORITY_AUDIO`）：

```
AudioRecord.read(ShortArray)        ── PCM 16-bit
        │
        ├─ rms() 計算振幅 ──────────► onAmplitude(amp)
        │
        ├─ SilenceDetector.isSilent() ─► 若為靜音則 continue（跳過）
        │
        ▼
MediaCodec (AAC-LC) queueInputBuffer ── 編碼
        │
        ▼
dequeueOutputBuffer ──► MediaMuxer.writeSampleData ──► 輸出 .m4a（MP4）
        │
        └─ acceptedFrames 累計 ──► currentPositionMs() / onPosition()
```

### 關鍵設計

- **緩衝區配置**：以 `AudioRecord.getMinBufferSize` 為基礎，必要時 `* 2` 並保證最小 4096 bytes；
  使用可重用的 `ByteArray` / `ShortBuffer` 以降低 GC 壓力。
- **立體聲降級**：若立體聲無法初始化（`getMinBufferSize <= 0`），自動改為單聲道。
- **暫停 / 繼續**：以 `paused` 旗標控制，暫停時仍持續讀取以避免緩衝堆積但丟棄資料。
- **靜音跳過**：僅在 `silenceSkip` 開啟時啟用 `SilenceDetector`；門檻以 dB 轉線性
  （`10^(dB/20)`），需低於門檻累計達 `minSilenceMs` 才判定為靜音（hangover）。
- **結束收尾**：`drainEnd` 送入 `BUFFER_FLAG_END_OF_STREAM` 並等待 drain 完成（逾時 2 秒），
  確保尾段資料寫入。
- **資源釋放**：`releaseAll()` 依序釋放 codec、muxer、音效與 AudioRecord，並以 `runCatching` 容錯。

### 音效（Audio Effects）

當 `effectsEnabled` 為 true，使用 `MediaRecorder.AudioSource.VOICE_COMMUNICATION` 並嘗試啟用：

- `NoiseSuppressor`（降噪）
- `AcousticEchoCanceler`（回音消除）
- `AutomaticGainControl`（AGC）

各音效以 `isAvailable()` 判斷，個別 `runCatching` 失敗不影響錄音。

### 輸出名稱

檔案命名格式：`REC_<epochMillis>.m4a`，儲存於 `files/recordings/`。
匯入檔案命名為 `IMP_<epochMillis><ext>`。

## 6. 前景服務（RecordingService）

- `foregroundServiceType="microphone"`，啟動即呼叫 `startForeground`（先以 placeholder 通知）。
- 支援 Action：`START`、`TOGGLE`、`PAUSE`、`RESUME`、`MARK`、`STOP`、`DISCARD`。
- **捨棄**：`DISCARD` 會停止引擎、刪除檔案與資料庫紀錄並結束服務（不保存內容）。
- **計時**：每 250 ms 更新 `RecordingStateHolder`；每秒更新通知；檢查提醒門檻與最長時間。
- **提醒**：於剩餘 10 / 5 / 3 分鐘發出高優先通知、`ToneGenerator` 提示音與震動。
- **WakeLock**：`PARTIAL_WAKE_LOCK`，持有時間為最長時間 + 1 分鐘，結束時釋放。
- **資料持久化**：停止或 `onDestroy` 時以 `NonCancellable` 更新錄音的長度、大小與聲道。
- **播放衝突處理**：若開始錄音時正在播放，會中止並移除前景狀態。

### 通知（RecordingNotifications）

- 頻道：`recording`（IMPORTANCE_LOW，常駐）、`alerts`（IMPORTANCE_HIGH，提醒）。
- 錄音通知提供「暫停 / 繼續 / 標記 / 停止」動作按鈕。

## 7. 播放（Media3）

- `PlaybackService` 繼承 `MediaSessionService`，內部建立 `ExoPlayer` 與 `MediaSession`。
- `PlaybackController`（`@Singleton`）以 `SessionToken` 建立 `MediaController`，將播放狀態映射為
  `NowPlaying`（`StateFlow`），並以 250 ms 週期更新位置。
- 播放音訊屬性：`USAGE_MEDIA` / `AUDIO_CONTENT_TYPE_SPEECH`。
- `play()` 以 `mediaId = recording.id` 識別項目；支援 `seekBy`、`setSpeed`、`togglePlay`。
- 錄音進行中（未暫停）會阻擋播放，避免回饋。
- 通知點擊以 `ACTION_OPEN_PLAYER` 回到播放頁。

## 9. 建置設定（Build Types）

`app/build.gradle.kts` 定義三種建置類型：

| Build Type | 壓縮（R8） | 資源縮減 | 簽署 | 用途 |
| --- | --- | --- | --- | --- |
| `debug` | 否 | 否 | Debug 金鑰 | 開發除錯 |
| `release` | 是 | 是 | 發行金鑰（需另行設定） | 正式發行 |
| `prerelease` | 是 | 是 | **Debug 金鑰** | 測試發行版本 |

`prerelease` 以 `initWith(release)` 繼承 release 設定，並覆寫：

- `versionNameSuffix = "-prerelease"`
- `signingConfig = signingConfigs.getByName("debug")`
- 產物：`app/build/outputs/apk/prerelease/app-prerelease.apk`

### ProGuard / R8 規則

`proguard-rules.pro` 目前保留 Media3 類別；Hilt 與 Room 由各自的 consumer rules 處理。
使用 `proguard-android-optimize.txt` 作為基礎規則。

### KSP

```kotlin
ksp {
    arg("room.schemaLocation", "$projectDir/schemas")
}
```

Room schema 匯出至 `app/schemas/`，並應納入版本控制。

## 11. 安全與隱私

- 錄音檔儲存於應用程式內部儲存空間，其他應用程式無法直接存取。
- 對外分享需經 `FileProvider` 且授予一次性讀取權限。
- 應用程式不進行網路傳輸；所有資料皆保留於本機。
- Pre-release 版本以 Debug 金鑰簽署，金鑰為公開測試用途，切勿用於正式發行。
